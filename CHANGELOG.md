# Changelog

What changed between the released versions of the test streams. The cards themselves (the 70 tests, their timing and
their expected results) are the same in every release unless a version says otherwise, so a result you recorded
against an earlier release stays comparable.

## Upcoming

Not released yet.

* **12 new cards (82 in all, 10:08 long)**, added to the original 70, which keep their ids; the
  start time and the test number of a card after an inserted one move. G03 (two separated rows of different colors),
  H02 (a pair for another channel between two copies of a command, UNSPECIFIED), S06 (a zero pair in the middle of a row,
  UNSPECIFIED), S07 (the display is enabled 12-18 valid frames after a loss of data), S08 (a valid pair resets the count of
  frames without data), A10b (Flash On over occupied text), A11 (attribute inheritance next to an erased cell and a written
  space), D10 (Text Mode data does not touch the caption), R07b (a PAC moves a roll-up by one row), R10b (a roll-up deeper
  than its base row allows), R12a (default base row after the only character was erased) and R12b (a roll-up resumed after
  Text Mode, UNSPECIFIED). The Expected text of A01 and R02 now says that the rows keep their grid rows. The reference model
  holds the display disabled for 15 frames after a loss of data and has a Text Mode memory. A result recorded against v1.2
  stays comparable for the cards that were already there.

* **SCC file of the caption data** (`build.py --scc`, or `--scc-only` for just the file). The field 1 caption data of the
  streams (CC1 and CC2) as an SCC file with drop-frame timecode, attached to the release as `*-field1.scc`: the same bytes
  as the streams at the same times, for tools that read SCC. Field 2 (CC3 and CC4) cannot be carried in SCC and is not in the
  file. The streams and the cards are unchanged.
* **The annotated screenshot of the README is generated by the build** (`python screenshot.py`): the card, its number, the
  test counter and the banner come from the schedule, so they follow the cards when the cards change, and the release
  workflow checks that the committed image is current (`--check`). Documentation only; the streams and the cards are unchanged.

* **MP4 version of each stream** (`build.py --mp4`, H.264 only). A constant-quality encode (CRF 21, about 0.4 Mbps, AAC
  audio) of the same captioned video, roughly a tenth of the size of the 4 Mbps constant-bit-rate transport stream
  (27 MB against 264 MB for the 720p59 stream). The captions are carried only in the H.264 SEI, as in the transport
  stream: there is no QuickTime `c608`/`c708` track.

* **Cards extended with codes found in another suite's stream.** A byte-level comparison with Rodrigo Madera's CEA-x08
  EIA-608 stream (https://github.com/madera/CEA-x08, v3.0, MIT) showed a few codes it sends that ours never did. The
  card list, timing and expectations of every other card are unchanged; the cards below carry the extra rows.
  * C02 now sends the transparent space (`0x11 0x39`) inside a run of red background.
  * A09c row 7 now continues from black to black underlined (`0x17 0x2F`, FAU) on its yellow background.
  * A03a and A03c now send column 1 with the indenting PAC for indent 0 (`0x50`, `0x51` underlined). The generator
    used to fold indent 0 into the white color PAC (`0x40`), so no card sent it.

## v1.2 (2026-10-14)

* **Fixed the `cc_data` padding and header** (CTA-708-E 4.3.5 and Table 2). Unused triplets were `F8 00 00`
  (`cc_valid` 0, `cc_type` 00), which that standard defines as "no CEA-608 waveform for this field" and not as padding,
  and which confused some downstream parsers; they are now `FA 00 00` (`cc_type` 10). The `cc_data` header was
  `0x40 | cc_count` (reserved bit clear) and, in H.264, a reserved byte of `0x00` written by ffmpeg's libx264 wrapper;
  Table 2 requires `0xC0 | cc_count` and `0xFF`. Both are corrected in the H.264 and MPEG-2 streams. The caption pairs
  themselves are unchanged, so no card changes.
* Developer documentation cites SCTE 128-1 and A/53 Part 4 for the caption wrapper and the marker bits.

## v1.1 (2026-10-13)

* **Reference slides** (new): for each format, a viewer (drop-down, Previous/Next) showing what every card should look
  like, drawn by a small CEA-608 decoder model from the stream's own caption data. Attached to each release as a
  `-reference.zip` and published at https://dheitmueller.github.io/cea608-conformance-suite/.
* Fixed the slide model for roll-up captions: with no caption on screen, the base row defaults to 15 (CTA-608-E C.15,
  p.75); the slides for card R09 showed row 3. The streams are unchanged.
* Documented the GitHub Pages setting that tag deployments need.

## v1.0 (2026-10-11)

* First stable release. Documentation screenshots updated (the 480i59 screenshot was removed); the streams are the same
  as v0.1.

## v0.1 (2026-10-11)

* Initial release: 70 test cards in two transport streams, 720p59 (16:9) and 480i59 (4:3 interlaced), H.264 or MPEG-2,
  with CEA-608 captions as ATSC A/53 `cc_data`.
